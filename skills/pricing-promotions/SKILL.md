# 定价与促销（Pricing and promotions）

下文中「商品」指本次运营所定价的对象：一件产品、某几个日期的某一房型、一个套餐，或一档票种。

一份价格提案就是：工具返回的几个数字、一次暂存变更、以及它的预览。运营者依据预览来决策。

## 每个数字从哪里来

- 先为每个商品读 `get_pricing_context`：当前价格、成本与 `margin_pct`、允许区间、两项上限、以及 `demand_signal`。
- 先讲上限，再讲数字：`max_price_delta_pct` 约束**永久**调价，`max_promotion_discount_pct` 约束**促销力度**。运营者要的幅度超过上限时，指出该上限并提出一个落在其内的数字（写在正文里或做成快捷选项），运营者选中后再暂存该数字；**不得**把超限版本描述为允许、**不得**先暂存以试探是否放行、**也不得**未经要求就用压到上限的版本顶替。
- 毛利要**引用**，不要**计算**。`margin_pct` 来自定价上下文；`margin_before_pct`、`margin_after_pct` 与 `margin_impact` 来自暂存变更记录——因此暂存备注里不放任何毛利结论。
- 金额一律按商品所用币种、照工具返回原样书写。
- 既定的重定价规则与价格带属于宿主配置，以定价上下文返回的区间与上限形式到达你这里；`min_price_basis` 说明下限的依据是该项成本还是店铺规则——当下限决定结论时，要说清是哪一种。你自己发起的动作，一次只暂存一次变更。
- 带选项的商品按变体定价：对商品调用定价上下文会返回每变体一行，你暂存的每一项都要指名变体 id。

## 调整的幅度

- 以运营者陈述的目标为锚（清掉滞销款、提升毛利、保住销量、填满特定日期），提出**能满足该目标的最小幅度**。
- 预期效果以**预期**口吻表述，取自 `demand_signal` 或节奏数字，并指名其依据。
- 适用时**先**给出非降价选项：缩短窗口、收窄范围，或维持不动。
- 对由 inventory-operations 移交来的滞销项，把它带来时的件数、库龄与节奏，与定价上下文给出的毛利空间合在一起看，说明数字指向哪一侧；只有运营者选中才暂存降价。

## 促销与绑定日期的动作

- 促销在同时具备**适用范围、力度与结束日期**之后才暂存；面对开放式折扣或全店折扣，应当**以提问的方式提出**，而不是替它填好。
- 有方向但窗口尚无日期的调价（「为春季推广」）属于**价格更新**：现在就暂存，并在备注中写入该假设；同时提出一旦拿到日期就把它转为绑定日期的促销。
- **让适用范围来选工具**：限于特定日期或晚上的动作走 `stage_promotion`（含加价情形）；`stage_price_update` 改变的是此后的基础价格，仅当被要求的正是这个时才用它。
- 绑定日期的建议要锚定**所涉日期**的入住率或售罄节奏，**绝不能**锚定季节平均值；按日期区间或档位分别给出，并附上驱动它的日期或「距当天还有几天」。节奏不支持的范围就不动。
- 星期几的名称取自返回的日期：在窗口旁写「周六—周日」之前先核对；不确定时只给日期。
- 促销会以低于其下限的价格售出任何所含项目时，须在回复中指出。

## 暂存与预览

- 每一次动作都经由 `stage_price_update` 或 `stage_promotion`；预览展示每项的调整前后与毛利影响。
- 暂存备注写**一句**说明该变更为何安全或值得做；`present_change_preview` 的标题与备注表达同一意思，各一句。
- 此处会遇到的护栏是：单次变更的项目数上限、变动幅度上限，以及受保护字段（如受监管的费用）。由于促销会到期，永久调价超过 `max_price_delta_pct` 时的替代方案就是绑定日期的促销；把它作为选项交给运营者选择，**不得**未经要求就用它顶替该调价。
- 费率建议以组件交付：一次暂存变更及其预览，或把数字放进 `present_metrics`、并在其前用一两句说明驱动因素。

## 执行流程

1. **读上下文**。对每个待调商品调用 `get_pricing_context`，取当前价、成本与 `margin_pct`、允许区间、两项上限与 `demand_signal`。判据：数字齐全，金额按原币种原样记录。
2. **先陈述上限**。写下 `max_price_delta_pct` 与 `max_promotion_discount_pct`。判据：上限出现在任何具体数字之前。
3. **校验幅度**。若所要求幅度越过上限，指名该上限并提出其内的数字；运营者选中后再暂存。判据：未暂存任何超限版本，也未用压顶版本顶替。
4. **定幅度**。以运营者的目标为锚，取能达成目标的**最小**幅度；预期效果以预期口吻表述并指名依据。
5. **先给非降价选项**。判据：缩短窗口／收窄范围／维持不动三项已考虑或已给出。
6. **定日期口径**。按所涉日期的入住率或售罄节奏取值，不使用季节平均；星期几名称须与返回日期核对。判据：节奏不支持的范围未被改动。
7. **暂存**。走 `stage_price_update` 或 `stage_promotion`（按适用范围选）。备注一句话；毛利只引用不计算。
8. **复核预览**。检查每项的调整前后与毛利影响，并指出任何会低于下限的所含项目。
9. **交付**。以暂存变更＋预览，或 `present_metrics`＋驱动因素说明收尾。

## 边界与降级

- **所要求幅度越过上限**：指名上限并给出其内的数字，交运营者选择；**禁止**暂存超限版本试探放行，**禁止**未经要求以压顶版本顶替。
- **促销缺适用范围／力度／结束日期之一**：不得暂存；面对开放式或全店折扣，改为**提问**。
- **窗口尚无日期**：按价格更新处理，在备注中写明假设，并提出日后转为绑定日期的促销。
- **无节奏数据**：不得用季节平均值顶替；说明所涉日期的节奏不可得，并只给出范围之外的选项。
- **星期几不确定**：只给日期，不给星期名称。
- **毛利相关**：只引用工具返回的 `margin_pct` 等字段；不得自行计算，暂存备注中不放毛利结论。
- **受保护字段或项目数超限**：说明该护栏并按未超限的范围重提，不绕过。
- **无网络或工具不可用**：改为人工按本流程的上限校验与期限规则整理方案，并在产出开头标注数据来源与缺失项。

## 质量自检

- [ ] 两项上限在任何具体数字之前已陈述。
- [ ] 无暂存的超限版本，无未经要求以压顶版本顶替。
- [ ] 调整幅度为满足目标的最小幅度。
- [ ] 预期效果以预期口吻表述，且依据已指名。
- [ ] 非降价选项（缩短窗口／收窄范围／维持不动）已考虑或已给出。
- [ ] 绑定日期的建议锚定所涉日期的节奏，未使用季节平均。
- [ ] 星期几名称已与返回日期核对，或已只给日期。
- [ ] 促销三要素（范围／力度／结束日期）齐全后才暂存。
- [ ] 毛利字段为引用而非计算，暂存备注中无毛利结论。
- [ ] 低于下限的所含项目已在回复中指出。
- [ ] 引用的资源路径全部存在，无占位符残留。
