# 翻译流水线编排（四道工序，中间产物解耦）

> 定位：把中文化里的「判断活」收窄到只该判断的地方。**拆的是工序与产物，不是技能**——
> 全部工序仍在本技能入口内执行，不另立门户。判定细则见 `localization-zh.md`，术语见 `glossary.md`。

## 为什么这样拆

- 早期批次「通读 → 翻译 → 自检」一条龙，耗时大头在通读定位与术语回查，且同词异译无人发现；
- 拆成技能会付三笔税（交接丢语感 / N 套门禁面 / 形态先行），拆成工序＋产物文件则零税：
  每道工序的输出是**可检查的文件**， redo 任何一道都不牵连其余。

## 工序一览

| 工序 | 性质 | 输入 | 输出 | 固化程度 |
|---|---|---|---|---|
| A 通读拆解 | 半判断 | 平台版源（EN） | `translation-plan__<slug>.md` | `make_translation_plan.py` 抽取，人只确认 [重写] 与疑难点 |
| B 术语落定 | 一次性判断 | plan 的 [决策] 项 | frontmatter 字段 + glossary 追加 | glossary 已有词直接用；新词回填 |
| C 逐段翻译 | 判断活 | plan + glossary | 译完的 SKILL.md / references | 我在环，不跨工序交接语感 |
| D 合成自检 | 确定活 | 译文 | `--out` 报告 + zip | 双门禁 + `pack_zh.py`，零改造 |

## 执行步骤

1. **A**：`python scripts/make_translation_plan.py <平台版技能目录> [--deep]`
   产出 plan（默认落在技能目录的父级）。核对三处：[重写] 段是否真占位、[决策] 字段、路径核对清单的口径（包内真实路径 vs 「上游 `<模块>` 包中的 `<文件名>`」）。
2. **B**：frontmatter 中文名与中文描述落稿；翻译中遇到的**无先例术语**先 grep 已交付 22 包，确认无先例才新造，并**立即追加** `glossary.md`（注明批次）。
3. **C**：按 plan 的标题树自上而下翻译。规则：`反引号内`不译；骨架 [重写] 段按源内容落为具体步骤与判据，不留套话；术语以 glossary 为准。
4. **D**：复跑双门禁（`port_skill.py self_check` + `check_localization.py`），对照 plan 检查 [重写] 清零、体量不缩水（分母陷阱见 SOP 第四节），然后 `pack_zh.py` 出交付 zip。

## 验收判据

- [ ] plan 文件存在且三处人工确认项（[重写] / [决策] / 路径口径）逐项有结论
- [ ] 译文无 glossary 之外的「新造术语」——如有，glossary 已回填
- [ ] 双门禁 0 FAIL；plan 中 [重写] 标记全部清零或改判说明理由
- [ ] 正文体量 ≥ 源（中文字符数显著增长）；代码块 / 表格数量与 plan 一致（无吞块）

## 边界

- plan 的骨架段判定是**启发式**（宁多报不漏报）：已交付包复跑会报「疑似占位」，属复核提示而非缺陷；
- 本流水线不改变 `localization-zh.md` 的任何判定口径；两者冲突时以 SOP 为准并回改本文件；
- 工序 B 只在首次接触新领域时是「重活」——glossary 越用越薄，这是设计目标。
