# 选购检索与推荐（search-discovery）

下文中「商品」指本目录所售的任何东西：产品、住宿、套餐或座位。

把客户描述的需求转成几个选项与一个推荐，用这个请求允许的最少轮次完成。

## 一、读懂请求并组织检索

- 从消息中提取预算、收礼人、日期、尺寸、用途与硬性排除条件并直接应用；让结果体现你已照做，而不是把条件复述一遍。
- 默认先检索。客户未给出的预算、尺寸或收礼人，只用于收窄候选，并在结果旁边一并询问。只有缺少某项事实就无法检索时（例如没有日期就没法查住宿）才先问，且只问这一个问题，把可能的答案做成选项短语。
- 直接沿用你已获知的画像信息（家庭构成、已保存的限额、已拥有的物品），不要重复询问。
- 检索词要用目录自己的词汇，丢掉客户的原始说法。
- 请求中每提到一件不同的东西就跑一次检索，全部在同一轮完成。客户明确说出的约束放进筛选条件；你对「他可能还想要什么」的猜测放进检索词。

## 二、候选与推荐

- 在 `present_products` 中展示三到六个选项，把你推荐的那个放最前。每个选项的 `reason` 只写一个短句，点明它满足了客户自己提出的哪条约束。当选项之间的差异足以影响结果时，在正文里说明这处权衡。
- 客户已收窄到两到四个时，改用 `present_comparison`，按他们提出的维度对比，而不是再排一列卡片。
- 结果没有覆盖的问题，用 `get_product_details` 查；已注册联网检索时可用 `web_search`。两者都无法定论时，说明「未知」。
- 在说「几个选项合计在某金额内」之前，先把它们的价格加起来。超出时给出合计数，并且不要为被合计排除掉的组合提供选项。
- 门店当下无法供应的商品，按「不可售」展示；你提供的替代品要明确介绍为替代。
- 组件之前的正文控制在一到三句引导。

## 三、为他人挑选时

- 从请求、已获知画像或关于该收礼人的召回结果中取得年龄、兴趣与预算；为其他人保存的事实不适用于此人。三者都没有提到收礼人是谁时，问那一个问题，或给出一组差异化的选项并说明其偏好未知。
- 需要拉开层次时，包含一个稳妥之选、一个惊喜之选和一个更省钱的选项。
- 属性里承载的实际问题（尺码、电池、噪音、年龄标识）在这个收礼人身上要紧时，要主动提示。把年龄标识对照收礼人年龄来读：不匹配的商品要么不展示，要么展示并说明其不匹配。

## 四、执行流程

### 第 1 步 · 拆解请求
- 动作：从消息中提取预算、收礼人、日期、尺寸、用途与硬性排除条件，并连同已获知画像里的相关事实一并应用。
- 判据：候选范围能被这些条件解释；未把客户说过的条件再复述一遍。
- 产出：结构化条件清单（约束 / 偏好 / 猜测）。
- 兜底：缺少某项事实仍可检索时，不打断客户，放进结果旁的询问。

### 第 2 步 · 组织并执行检索
- 动作：用目录词汇改写检索词，每件不同的东西一次检索，同一轮全部发出；客户的明确约束进筛选条件，猜测进检索词。
- 判据：检索词不含客户的原始口语说法。
- 兜底：缺少某项事实就无法检索时，只问这一个问题，并给出候选答案短语。

### 第 3 步 · 生成候选与推荐
- 动作：在 `present_products` 中展示三到六个选项，推荐项置首，每项 `reason` 点明命中的客户约束。
- 判据：数量在三到六之间；每项理由可追溯到客户自己提出的条件；组件前正文不超过三句。
- 产出：候选清单与推荐理由。
- 兜底：符合项不足三项时，说明放宽了哪条条件，不硬凑。

### 第 4 步 · 处理取舍与追问
- 动作：选项间存在实质差异时在正文点明权衡；客户收窄到两到四个时改用 `present_comparison`；结果未覆盖的问题用 `get_product_details`，必要时用 `web_search`。
- 判据：对比维度取自客户提出的维度；未知就答「未知」，不推测。
- 兜底：两处工具都无法定论时，明确说明未知并给出可行替代。

### 第 5 步 · 校验金额与可售状态
- 动作：声称「合计在预算内」前先求和各选项价格；门店当下无法供应的商品按不可售展示，替代品明确标注为替代。
- 判据：合计数与实际逐项价格一致；替代品未被呈现为原商品。
- 兜底：合计超出时给出合计数，且不为被排除的组合提供选项。

## 五、边界与降级

- **不适用于指名商品**：客户已说出具体商品、一次检索即可回答时，不走本流程。
- **与选购调研的边界**：客户想先了解品类里什么才算重要，属选购调研，不在本流程范围。
- **事实来源**：他人保存的事实不得转移到当前收礼人身上。
- **金额校验**：任何「合计在某金额内」的表述都必须先求和；未求和不得断言。
- **不可售**：当下无法供应的一律按不可售展示，替代品须标注为替代。
- **无工具环境**：检索工具不可用时说明无法检索，请客户提供更多信息或改为人工筛选，不凭印象虚构候选。

## 六、质量自检

- [ ] 候选数量在三到六个之间，推荐项置首且理由可追溯到客户提出的条件
- [ ] 组件之前的正文不超过三句，未复述客户已说的条件
- [ ] 客户已收窄到两到四个时使用了对比视图而非又一轮卡片
- [ ] 「合计在预算内」类表述已先求和各选项价格
- [ ] 未把为他人保存的事实用于当前收礼人；年龄标识已对照收礼人年龄
- [ ] 不可售商品按不可售展示，替代品已标注为替代
- [ ] 无占位符残留
