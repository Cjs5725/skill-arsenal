# 目标规划（planning-goals）

下文中「商品」指本目录所售的任何东西：产品、住宿、行项或座位。

交回一份计划：客户能一眼看全、能只改其中一块、能在自己选定的时机动手。先把步骤定下来，再把商品挂到步骤上。

## 一、搭框架

- 五个事实决定一份计划：目标、涉及谁、在哪里发生、何时必须就绪、预算。请求与你被给定的画像给出哪个就用哪个。缺失的每一项按一个**写明的整数级假设**推进（「按两人计」「未给预算，取中档」），客户一句话就能纠正。
- 按客户实际推进的线（一天、一个人、一个房间、一个阶段）把目标切成三到八步，每步用客户自己的说法命名。
- 给出预算时，按整数把它分摊到各步并展示分摊结果，份额大的落在承载目标的那几步上。
- 请求一旦点明目标，搭框架与填空要在同一轮完成：跑检索，按天、按人或按时段各提一步并挂上商品，让目录本身的空缺与替换去承担提问的作用。步骤内的选择（某样买几份、这一步要不要）写成该步上的假设，不构成扣住商品的理由。
- 只有当**步骤本身**存疑时才先单独发步骤：客户问「从哪开始」，或目标沿多条线切分。那一轮的 `present_plan` 只带标签与分摊、不带商品（唯一一次不带商品的场景），旁边配一个最可能改变整体架构的问题及其候选答案；商品下一轮再来。问题不得脱离计划单独发出。

## 二、填空

- 每一步各跑一次检索，全部在同一轮发出。
- 用量按搭框架时的事实定，并把定出的数量写进计划。
- 客户已经具备的步骤，标记为「已具备」：不为它跑检索，也不给它要买的东西。
- 每步挂一个选择。只有当两难无论如何都要客户付出代价时（例如价格与耐用度相抵），才追加第二个选项。
- 只有本轮对话中的某次检索返回了该步的商品，才能把这一步算作已覆盖。空结果与已声明约束的规则**逐步**适用：唯一命中但超出该步份额的，仍留在该步上并标「超预算」；重试之后仍无结果的，才算空缺。
- 不要围绕缺货商品做规划：给该步一个在售选项，或注明该商品不可得、其余步骤照常推进。

## 三、呈现

- 用 `present_plan`：每步一个短标签、一行细节、该步的商品（上面那次搭框架轮除外），有选择时你的推荐置首。组件前的正文控制在一到两句。
- 客户需要的是知识而非商品时（先后顺序、该预期什么），改用 `present_guide`；凡有网页内容支撑，都要列出 `sources`。
- 部署环境中若注册了专为本计划形态设计的呈现工具，按其规则替用 `present_plan`。

## 四、改动

- 改一步只动那一步；计划的其余部分，含客户此前的修改，保持原样。改后重新呈现计划。
- 客户说「加上」「买」「结账」之后，把他点名的集合（某一步、某个商品或整份计划）加入，并用一行说明加入了什么。

## 五、执行流程

### 第 1 步 · 取齐五个事实
- 动作：从请求与画像中提取目标、涉及谁、地点、截止时间与预算；缺失项各给一个写明的假设。
- 判据：五个事实均有取值，缺失项标注为假设且客户可一句话纠正。
- 产出：搭框架用的事实清单。
- 兜底：目标本身不明时，先在当轮问清目标，再进入拆分。

### 第 2 步 · 切分步骤并分摊预算
- 动作：按客户的工作线把目标切成三到八步，用客户的说法命名；有预算则按整数分摊并展示。
- 判据：步数在三到八之间；命名取自客户用语；分摊份额大的步骤对应承载目标的步骤。
- 兜底：客户有困惑但不清楚边界时，把最可能改变架构的一个问题连同候选答案放在计划旁，不单独提问。

### 第 3 步 · 逐步骤检索并挂商品
- 动作：每步各跑一次检索、同一轮发出；按框架事实定数量并写进计划；已具备的步骤不检索。
- 判据：某步只有本轮检索返回过其商品才算「已覆盖」；唯一命中超份额的标「超预算」；重试后仍无结果才算空缺。
- 兜底：商品缺货时改给在售选项或注明不可得，不围绕缺货商品规划。

### 第 4 步 · 呈现计划
- 动作：用 `present_plan` 输出每步的标签、一行细节与该步商品，推荐置首；需要知识而非商品时改 `present_guide` 并列出 `sources`。
- 判据：组件前正文不超过两句；有网页依据时来源已列出。
- 产出：可视化计划。
- 兜底：环境未注册 `present_plan` 时以结构化文字清单呈现，保持同等信息量。

### 第 5 步 · 处理改动与加购
- 动作：改动只作用于被点名的那一步，其余部分含既有修改保持原样，改后重新呈现；客户说加购时把点名的集合加入并说明。
- 判据：未牵连未点名的步骤；加购后用一行说明加入了什么。
- 兜底：改动涉及多步时，先确认改的是哪一步再动手。

## 六、边界与降级

- **假设必须写明**：缺失事实一律以写明的假设推进，不得静默取值。
- **覆盖判定**：只有本轮对话内检索返回过的步骤才算已覆盖，不得凭印象认定。
- **唯一的无商品场景**：只有「步骤本身存疑」那一轮可以不带商品，且必须同时给出计划。
- **提问方式**：问题不脱离计划单独发出；候选答案以选项短语呈现。
- **无检索环境**：无法检索时说明该步商品无法确认，先交付步骤框架，商品留待可检索时补齐。
- **能力边界**：本流程不含改价、改库存等动作，属于定价与库存流程。

## 七、质量自检

- [ ] 五个事实齐全，缺失项均以写明的假设呈现且可一句话纠正
- [ ] 步数在三到八之间，命名取自客户用语
- [ ] 每步的商品都来自本轮检索返回的结果，无凭印象挂载
- [ ] 超出该步预算份额的唯一命中仍留在该步并标注「超预算」
- [ ] 改动的只有被点名的那一步，改后已重新呈现
- [ ] 组件前正文不超过两句
- [ ] 无占位符残留
