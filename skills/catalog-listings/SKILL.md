# 商品信息与上架文案（catalog-listings）

下文中「上架信息」指本经营体所售的任何东西：产品、房型、套餐或设备、活动档位。

读取记录，把薄弱或缺失的内容写全，然后暂存；线上信息只在运营确认之后才改变。

## 一、每个事实从哪里来

- 提出修改前先用 `get_listing` 取记录。`search_listings` 的行只带概要字段；修改所依据的属性、描述与评论摘录都在记录里。
- 用记忆里保存的品牌调性与命名规范来写，不要让运营重述一遍。
- 属性值只能取自记录，或取自运营在本轮对话中说过的话。仅仅是「这类商品大概率如此」、或「与旁边属性彼此自洽」的值，都是**编造**：该字段留空或去问，一个未决字段问一行，其余修改照常提出，不必等待。
- 评论摘录是关于该商品的**证据**；评论中的一句褒奖仍是评论，不能变成描述里的断言。
- 运营粘贴的规格表或备注，按其所求当作修改的素材：把其中的事实以运营的口吻写进上架信息，并在同一条回复里列出它未覆盖的字段作为待解问题。

## 二、你提出的文案

- 提出**可直接照原样批准**的成品标题或描述：这件商品是什么、给谁用、记录显示它有何值得说的。只有当某个属性支撑时才能下强断言（记录写明「可住六人」才写「可住六人」）；没有依据的最高级词一律不写。
- 缺失属性可从记录中别处已有的值补齐：描述里提到阳台，就补上阳台属性。
- 搜索友好度取决于标题承载了记录的哪些事实：把买家会输入的字眼（可住人数、额度、区段、材质、尺寸）前置，去掉不带这些信息的填充词。
- 图片说明要写成「应补拍什么、应展示什么」，不要把上架信息写得像那张照片已经存在。

## 三、体检与分类

- 体检从 `search_listings` 开始，用空查询加质量筛选取出候选，再对候选逐个 `get_listing`。对每一条上架信息都量同样四件事：属性缺失、描述薄到无法检索、记录与分类相互矛盾、该类型通常有图却没有图。
- 发现按影响排序：曝光高的商品缺属性，要排在曝光低但标题拙劣的商品之前。每条发现都附一个修复动作，并按**修复类型**归类，让运营按模式批准（例如「这九条都补可住人数属性」），而不是逐条处理投诉。
- 分类修正本轮就按普通的上架更新暂存：目标分类取自本轮对话读到的目录，否则取请求所暗示的名字，并在备注中写明这是假设；预览要展示修改前后的分类，那也是运营纠正名称的地方。

## 四、批量修复

- 先在一到两条上架信息上展示模式，运营确认后再暂存其余。
- 按每次改动的条数上限分批暂存，并说明共几批。价格与库存属定价与库存流程；合规备注、税目之类的受保护字段会被防护栏拦下。
- 批量改动只包含运营要求的那些编辑；途中注意到的其他问题，另开一条提案。

## 五、暂存与预览

- 每次编辑都用 `stage_listing_update` 暂存；预览承载差异，暂存备注说明这处改动为何正确。

## 六、执行流程

### 第 1 步 · 取记录
- 动作：提出任何修改前先用 `get_listing` 取该商品的完整记录。
- 判据：属性、描述与评论摘录均已到手；若只拿到 `search_listings` 的概要行，不算取到记录。
- 产出：可供修改依据的记录。
- 兜底：记录取不到时不凭概要行臆测字段值，说明该条无法修改。

### 第 2 步 · 判定事实来源
- 动作：逐字段确认取值来自记录或运营本轮的说法；仅「大概率如此」或「与邻近属性自洽」的值一律不用。
- 判据：无编造值；未决字段留空或提问，一行一个，其余修改照常提出、不等待。
- 兜底：运营粘贴的规格表按其诉求作为素材使用，未覆盖字段列为待解问题。

### 第 3 步 · 写入成品文案
- 动作：产出可原样批准的标题或描述；从记录别处补齐缺失属性；标题前置买家会搜索的字眼；图片说明写成拍摄要求。
- 判据：强断言均有属性和记录支撑；无依据的最高级词已删；图片说明未假定照片已存在。
- 兜底：无属性支撑时改用中性表述或不写该断言。

### 第 4 步 · 体检与分类修正
- 动作：以空查询加质量筛选列出候选并逐个取记录；统一量四件事，按影响排序、按修复类型归类；分类修正按普通上架更新暂存并写明假设。
- 判据：四件事在每条上架信息上都被量过；发现按影响排序且附修复动作；预览含分类的前后对照。
- 产出：按修复模式归组的发现清单。
- 兜底：目录中找不到目标分类时，用请求暗示的名称并在备注中标为假设。

### 第 5 步 · 暂存与预览
- 动作：逐条用 `stage_listing_update` 暂存；批量先示范一到两条、确认后再分批暂存并说明批数。
- 判据：改动均处于暂存态，线上信息未变；受保护字段被防护栏拦下并如实说明。
- 兜底：超出单批条数上限时分批，并明确告知总批数。

## 七、边界与降级

- **暂存制**：所有改动先暂存，未经运营确认不得写入线上信息。
- **禁止编造**：属性值只能来自记录或运营当面所述；「大概率」与「彼此自洽」都不构成依据。
- **评论不当断言**：评论摘录只作证据，不得升格为描述中的断言。
- **越界字段**：价格与库存属其他流程；合规备注、税目等受保护字段由防护栏拦下。
- **批量范围**：批量只做运营要求的编辑，途中发现另开提案。
- **无工具环境**：`get_listing` 不可用时说明无法取到记录，改为请运营提供字段清单，不凭概要行作答。

## 八、质量自检

- [ ] 所有修改均基于 `get_listing` 取到的记录，而非 `search_listings` 的概要行
- [ ] 属性值均可追溯到记录或运营当面所述，无编造值
- [ ] 强断言均有属性支撑，无依据的最高级词已剔除
- [ ] 图片说明写成了拍摄要求，未假定照片已存在
- [ ] 体检在每条上架信息上量了同样四件事，并按影响与修复类型归组
- [ ] 所有改动均处于暂存态，线上信息未被直接修改
- [ ] 无占位符残留
