# 业绩洞察（Performance insights）

下文中「分部」指本次运营所报告的任何单位：一个品类、一个商品、一处房源、一个套餐，或一场活动。

给运营者一个**可据以行动**的结论、支撑它的数字、以及它所依据的比较，并说明这些读数分别来自哪里。

## 数字从哪里来

- 先从 `get_business_snapshot` 取所问期间的头部数字、上一期（`compare_to` 与变化百分比），以及后续所有数字都要对照的预警计数。若问题只涉及经营的一部分，再用 `query_metrics` 查某一指标随时间的走势，并收窄到相应分部。
- 毛利与库存取自 `get_pricing_context` 与 `get_listing`；活动花费与收入取自 `get_campaign_performance`——快照不携带这些。
- 后端没有的序列（报错、空序列、返回的指标名与所问不符）报告为**不可得**，并说明这让哪个问题仍然悬着。
- 凡自行推算的数字（年化速率、缺口、按当前速度的售罄日），须在旁列出其输入。
- 返回序列中的最新日期，就是数据覆盖到的最新日期。越过它的期间是**部分期间**；与完整期间比较前先说明这一点。

## 比较

- 按问题选择比较期并**指名**：问这周过得如何就用上一期；可能是季节性的波动就用去年同期；问题关于某项变更，就用该变更的前后。
- 部分期间应与基准期**对应的那一段**比较；做不到就说明这是「部分对完整」的比较，并给出两个截止日期。
- 问题若是相对可比对象的节奏（本轮对同一事物的上一轮，或对同周期同点位的同类），就把可比对象作为**另一条** `query_metrics` 序列取出，指名它，并说明为何可比。
- 两条序列以不同名称返回时，按返回原样都放进 `present_metrics`。二者只有期间不同时，它们**同名**：最后查当期，先呈现当期，并在正文中给出可比对象的数字及其期间。无论哪种，都要给出**同一周期点位**上的差距，而不是两个总量。
- 数据中没有可比对象时（首轮运行、首个旺季），如实说明，按它自身的口径给出节奏，并提供数据中最接近的替代物并标明它是替代物。**不得凭记忆中的类似案例拼造可比对象。**

## 解释一次变动

- 先说什么动了、动了多少、相对哪个基准；然后再去查。
- **先确认变动，再解释它。** 部分期间、序列缺口、异常基准，能解释掉许多「看起来的下跌」；若原因在此，说明并就此打住。
- **定位**：按分部查询，指名占该变动最大份额的分部，并给出其占比。
- **区分结构与水平**。均价下降，既可能是单价降了，也可能是更便宜的品占比变大；说明返回的序列显示的是哪一种，或说明在未按分部查询之前无法分辨。
- 用同一日期区间的工具数据核对候选原因：活动窗口取自 `get_campaign_performance`，断货或售罄取自 `get_inventory_alerts` 或商品记录，价格变动取自 `get_pending_changes` 或本轮对话中应用过的变更。
- **只有当时间点吻合、且变动落在它本会影响的那个分部时，才能称之为原因**；否则报告为相关性，并指名哪一项读数能给它定论。
- 用与证据相称的措辞标注置信度：数据支持时称「发现」，部分支持时称「线索」，都不支持时称「数据中不可见」。

## 运营者陈述过的目标与规律

- 本轮对话中陈述的目标，或 `recall_memories` 中保存的目标，能把一份总结变成**进度报告**：迄今数字、期间已过的比例、以及余下期间所需均值——均由返回数字算出。**不得提供运营者未曾陈述的目标。**
- 判定某次波动是否异常之前，先回想运营者陈述过的季节规律，并说明它符合或不符合哪一条。本流程中出现的目标或规律，用 `save_memory` 存下，供日后的总结对照。

## 呈现答案

- 以 `present_metrics` 收尾。每个选项都须是**本轮对话中某工具返回过的**度量，用该工具的名称、并带其分部（`sales`、`sales:kids-room`、`conversion_rate`）。单日数值、两条序列之差、以及预测，都不算选项，它们属于正文。
- `present_metrics` 因「无据可依」被拒时，重新呈现已检索的序列，并把选项更正为工具返回过的名称。
- 组件之前，先给出结论及其基准（「销售较上周下降 12%，其中一个品类占了其中 9 个百分点」）、所用的比较、以及那条会改变读法的注意事项。
- 变动可追溯到某个运营动作时，把最后一个快捷选项设为通往执行该动作的流程的移交入口。

## 执行流程

1. **定问题与期间**。确认所问的指标、期间与分部。判据：问题可复述为一句「哪个指标、哪段时间、哪一部分」；含糊则先澄清。
2. **取基准底数**。调用 `get_business_snapshot`，取头部数字、上一期（`compare_to` 及变化百分比）与预警计数。判据：后续每个数字都有可对照的底数。
3. **取细分序列**。需要时用 `query_metrics` 取单指标随时间走势，并按分部收窄；毛利／库存补 `get_pricing_context`、`get_listing`；活动数据补 `get_campaign_performance`。
4. **确认数据覆盖**。判据：识别出返回序列的最新日期；若所问期间越过它，标记为**部分期间**。
5. **选定并指名比较期**。判据：比较期与问题匹配且已明确说出；部分期间与基准期对应段比较，并给出两个截止日期。
6. **先确认变动再解释**。判据：已排除部分期间、序列缺口、异常基准三种解释；命中其一即说明并终止解释。
7. **定位分部**。按分部查询，指名占变动最大份额者并给出占比；区分结构变化与水平变化。判据：无法分辨时明说「需按分部查询才能判断」。
8. **核对候选原因**。用同时段工具数据核对时间点与影响范围。判据：只有时间吻合且变动落在受影响分部时才称「原因」，否则称「相关性」并指名可定论的那项读数。
9. **标注置信度**。用「发现／线索／数据中不可见」三档，与证据强度相称。
10. **呈现**。以 `present_metrics` 收尾；选项须为工具返回过的度量名与分部；结论及其基准、所用比较、关键注意事项写在组件之前。

## 边界与降级

- **后端无该序列**（报错／空／指标名不符）：报告为不可得，并说明哪个问题仍然悬着；不推测数值。
- **部分期间**：与基准期对应段比较，并给出两个截止日期；不得与完整期间直接比总量。
- **无可比对象**：如实说明，按自身口径给节奏并给出标明了的最近替代物；**禁止凭记忆拼造可比对象**。
- **无法区分结构与水平**：明说需按分部查询才能判断，不二选一猜。
- **原因证据不足**：只能报相关性，并指名可定论的那项读数；不得直接下因果结论。
- **运营者未陈述目标**：不提供目标，只报告实际数字与节奏。
- **`present_metrics` 被拒**：重新呈现已检索序列，并把选项更正为工具返回过的名称。
- **无网络或工具不可用**：改为人工按本流程的比较与置信度规则整理已有数据，并在开头标注数据来源与缺失项。

## 质量自检

- [ ] 结论附带基准，且基准已明确说出。
- [ ] 比较期与问题匹配，部分期间已按对应段比较并给出两个截止日期。
- [ ] 解释变动前已排除部分期间、序列缺口与异常基准三种解释。
- [ ] 最大份额分部已指名并给出占比。
- [ ] 结构变化与水平变化已区分，或已明确说明无法分辨。
- [ ] 「原因」一词仅在时间吻合且变动落在受影响分部时使用；否则用「相关性」。
- [ ] 置信度用「发现／线索／数据中不可见」表述，与证据强度相称。
- [ ] `present_metrics` 的每个选项都是本轮工具返回过的度量名及其分部。
- [ ] 未提供运营者未曾陈述的目标，未凭记忆拼造可比对象。
- [ ] 引用的资源路径全部存在，无占位符残留。
